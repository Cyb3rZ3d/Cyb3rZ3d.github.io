AWS Purple Team Detection Project

Intrusion Detection and Hacker Exploits (CSEC 5350)

A controlled AWS attack-and-detect environment connecting reconnaissance and Apache vulnerability testing to centralized telemetry, SIEM investigation, IOC analysis, MITRE ATT&CK mapping, and detection development.

View GitHub Repository All Projects

Project Objective

Simulate authorized adversary activity against an Apache web server, collect the resulting Linux and web telemetry, and determine how the evidence can support repeatable defensive detections.

Environment

Three AWS-hosted roles were used: Kali Linux as the attacker, Ubuntu and Apache as the target, and the ELK Stack as the centralized defender and SIEM platform.

Outcome

Patched Apache 2.4.58 rejected both controlled CVE-style requests while ELK captured the GET and POST telemetry for KQL investigation, IOC analysis, and ATT&CK mapping.

Architecture and Data Flow

Attacker Kali Linux Nmap • curl
→
Target Ubuntu + Apache Web and system telemetry
→
Pipeline rsyslog + Logstash Collection and processing
→
Defender Elasticsearch + Kibana Investigation and detection

Attack-to-Detection Workflow

  1. Reconnaissance Identified reachable services, open ports, and the Apache attack surface using Nmap.
  2. Vulnerability Analysis Investigated Apache CVE-2021-41773 and CVE-2021-42013 within the authorized environment.
  3. Controlled Testing Generated non-destructive HTTP activity to create observable path-traversal and exploitation telemetry.
  4. Centralized Logging Forwarded Apache and Ubuntu events through rsyslog and Logstash into Elasticsearch.
  5. SIEM Investigation Used Kibana and KQL to analyze source activity, request paths, timestamps, and repeated behavior.
  6. Detection Development Translated observed behavior into IOC, ATT&CK, and behavioral detection opportunities.

Detection Focus

  • Repeated reconnaissance from a single source
  • Suspicious or encoded path-traversal sequences
  • Requests targeting sensitive filesystem locations
  • Reconnaissance followed by exploitation activity
  • Correlation of attacker actions with target logs
  • Behavior-based detection beyond single IP indicators
